01FOUNDATIONS3 MINBeginner

So, what is the cloud?

Understand what happens behind the scenes when you use an app, save a file, or launch a server.

Open field note ↗

Cloud computing is on-demand access to computing resources over the internet. Instead of buying and maintaining your own hardware, you rent what you need from a provider and scale it as demand changes.

Try this: Name one app you use that stores or processes your data in the cloud.

02FOUNDATIONS4 MINBeginner

IaaS, PaaS, SaaS

Three service models, one useful question: how much of the stack do you want to manage?

Open field note ↗

IaaS rents building blocks like virtual machines. PaaS adds a managed environment for deploying apps. SaaS gives you a finished application. As you move from IaaS to SaaS, the provider manages more of the underlying stack.

Try this: Sort email hosting, a virtual machine, and a managed app platform into these three models.

03FOUNDATIONS4 MINBeginner

Public, private, and hybrid cloud

Learn the main deployment approaches and why organizations sometimes combine them.

Open field note ↗

Public cloud resources are delivered by a provider over shared infrastructure. A private cloud is dedicated to one organization. Hybrid cloud connects cloud environments with private infrastructure; multi-cloud uses services from more than one provider.

Try this: Consider which data, compliance, or existing-system requirements might influence a deployment choice.

04ARCHITECTURE4 MINIntermediate

Choosing a cloud provider

A grounded way to compare AWS, Microsoft Azure, and Google Cloud beyond the brand names.

Open field note ↗

All three offer global infrastructure and broad service catalogs. Compare the services your workload actually needs, your team's existing skills, regional availability, support, and the total cost of a realistic design.

Try this: Pick a workload and write down its must-haves before comparing providers.

05ARCHITECTURE4 MINIntermediate

Regions, networks, and resilience

See how cloud locations and virtual networks connect applications and help keep them available.

Open field note ↗

A region is a geographic area; availability zones are isolated locations within it. Virtual networks let you define how cloud resources communicate. Using multiple zones can reduce the impact of a single-zone outage, while multi-region designs can address larger disruptions and latency.

Try this: Trace how a user request reaches an application and its data store.

06ARCHITECTURE5 MINIntermediate

Compute, storage, and databases

Get familiar with the building blocks behind most cloud applications and when each is useful.

Open field note ↗

Compute runs application code on virtual machines, containers, or serverless functions. Object storage holds files and backups; block storage attaches disks to machines. Relational databases organize structured records, while NoSQL databases support other data models and access patterns.

Try this: Match an image archive, a web server, and a customer order table to suitable cloud services.

07ARCHITECTURE4 MINIntermediate

Containers and serverless

Compare two ways to package and run applications without managing every server directly.

Open field note ↗

A container packages an application with its dependencies so it behaves consistently across environments. Serverless services run code or applications without requiring you to manage the underlying servers, though you still configure and monitor the service. Kubernetes orchestrates containers at scale and is not necessary for every app.

Try this: Compare the operational control you need with the amount of infrastructure you want to manage.

08SECURITY5 MINIntermediate

Cloud security and shared responsibility

Understand what providers secure, what you still own, and how access should be granted.

Open field note ↗

Providers secure the underlying cloud infrastructure, while customers remain responsible for their data, identities, access settings, and workloads. The exact split depends on the service. Use identity and access management to give each person or application only the permissions it needs, and protect data with encryption and backups.

Try this: Review who can access a test project and remove permissions that are not needed.

09OPERATIONS4 MINIntermediate

Monitoring, backups, and recovery

Plan how to spot problems, restore important data, and recover from service interruptions.

Open field note ↗

Monitoring tracks signals such as availability, latency, and errors so teams can investigate issues. Backups create recoverable copies of data; disaster recovery describes how services are restored after a major disruption. Test restores regularly because an untested backup may not meet recovery needs.

Try this: Decide how much data loss and downtime a simple project could tolerate.

10OPERATIONS3 MINBeginner

Keep cloud costs in view

Build a few sensible habits for visibility before your first bill becomes a surprise.

Open field note ↗

Tag resources by owner or project, set budget alerts, review usage regularly, and remove resources you no longer need. Budgets notify you about spend; they do not automatically cap it, so pair alerts with clear ownership.

Try this: Set a small test budget and an alert before experimenting with paid services.
